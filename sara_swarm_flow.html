SARA SWARM — CHAIN OF COMMAND

How each request flows through Sara's model team (flow chart)
⬇
USER REQUEST
▼
STEP 1 — TASK CREATOR / ROUTER Which worker handles this task?
(small checker model picks the role)
▼
CODER
WEB_SEARCH
PRIMARY
▼
STEP 2 — WORKER Produces the response
(coder / web_search / primary)
▼
STEP 3 — CHECKER ONLY asks: "Was the task completed?"
(YES or NO — nothing else)
▼
YES → DONE (return answer)
▲
NO → CONTINUE LOOP
▼
STEP 4 — REPROCESS IN A DIFFERENT LIGHT Different model + different approach
(up to 3 rounds, then give best effort)
▲
loop back to STEP 2 (new attempt)
▼
STEP 5 — SKILL DETECTOR Save reusable procedure?
(saves as SKILL.md if reusable)
▼
STEP 6 — SELF-IMPROVE If stuck, create a new tool
(grow her own tools)
Why the checker only says YES/NO: its answer is the trigger for the continue loop — YES = task done, loop STOPS. NO = reprocess in a different light, loop STARTS. Nothing else is needed for that decision.

Models can have MORE THAN ONE job. e.g. the checker also acts as the task router and skill detector.
